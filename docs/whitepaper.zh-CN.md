# DSH Token Saver 白皮书

## 摘要

DSH Token Saver 是 DeepSeek Harness 的一个插件，它减少模型必须阅读的文本量，同时不改变模型能做什么。它在 Host 把工具结果交还给 agent 的位置压缩输出，折叠重复的搜索结果，把可选的提示词塑形文本作为系统提示词 section 注入，并在本地回答一小类特征明确的请求。默认的 `conservative` 模式会裁剪和折叠工具输出；其他优化默认关闭，都可以通过配置开启或关闭，并且在出错时一律放行原始内容。

本文说明插件为什么存在、背后的设计原则、如何建立在 DSH 的扩展点上，以及未来可能的方向。它是设计文档，不是功能清单。功能清单见 [README](../README.zh-CN.md)。

## 1. 问题

agent 的上下文窗口就是它的工作记忆。系统提示词、对话历史，以及越来越多的工具输出都会占用它。一次 `git diff`、`find`、测试日志，或者对大目录的 grep，可能比任务本身消耗更多上下文。模型可用于推理的空间随之减少，harness 也不得不更早地做压缩。

这些文本大多并非无用，只是体量过大。一个 diff 有几百行相关内容和几千行未改动内容；一次 grep 有三十个匹配和四万行上下文；一份构建日志有一条错误和一万行进度输出。

最直接的做法是全部截断，但这不安全：截断可能删掉唯一重要的那一行，也可能删掉告诉下游工具"内容不完整"的标记。更好的做法是在 Host 同时知道工具身份和结果形状的接缝处压缩，按形状选择策略，并让原始内容通过标记仍然可达。

## 2. 愿景

让上下文效率成为 harness 的属性，而不是用户的习惯。

插件应当：

- **关闭时不可见。** 默认安装不改变任何面向模型的行为。
- **开启时可预测。** 相同输入和配置产生相同输出。
- **失败时安全。** 压缩逻辑的缺陷绝不能破坏请求。
- **报告时诚实。** 节省量以字节计量，并明确说明。
- **可组合。** 与其他插件协作，而不是独占请求管线。

## 3. 设计原则

### 3.1 压缩接缝，而不是请求

DSH 为工具结果提供了 post-execute 决策点。这个接缝拥有工具名、参数、结果，以及返回最终决策的 `next()`。它适合压缩：插件能看到模型将看到的内容，也能在不产生副作用的情况下放弃。插件不改写组装后的提示词，也不改写 LLM 请求。

### 3.2 只处理工具输出

插件只压缩工具结果。它不触碰用户消息、助手消息、系统提示词（通过受支持的 prompt section API 除外），也不触碰结构化工具值。工具输出是体量所在，也是对有损压缩最说得通的地方。

### 3.3 绝不压缩错误

错误结果是诊断证据。裁剪它可能隐藏故障。插件原样返回错误结果。

### 3.4 严格更小，否则不变

只有当压缩结果非空且严格小于原文时才被采用。无法改善文本的过滤器返回原文。

### 3.5 失败放行

每个策略都有包裹。检测器异常、正则异常、结果形状异常或遥测写入失败，都会返回上游决策。请求路径不会因为插件而抛错。

### 3.6 配置显式

默认的 `conservative` 模式会裁剪和折叠过大的工具输出。其他会改变模型输入的行为——RTK、提示词塑形、本地响应、压力压缩——都需要主动开启。非法值在激活时失败，而不是被静默转换。

### 3.7 计量字节，而不是 token

插件能精确统计 UTF-8 字节，但无法精确统计模型 token，因为分词取决于模型和提供方。把字节报告成 token 是一种会随看板累积的谎言。插件报告字节，并说明这一点。

## 4. 系统架构

### 4.1 分层

```
DSH Host
  ├── tools/post-execute ──> 压缩管线 ──> 截断 / grep 折叠 / RTK
  ├── agent/pre-step ──────> 压力检查 ──> 压缩引擎（副作用）
  ├── systemPrompt.section > Caveman / Ponytail 文本
  └── llm/stream ──────────> 本地响应流（其余情况只读）
```

插件有四个入口和一个共享状态对象。入口彼此独立：关闭其中一个不会影响其他入口。

### 4.2 压缩管线

`decidePostTool` 是执行、结果和配置的纯函数。它按顺序应用：

1. 资格检查（模式、包含/排除列表、错误、仅有结构化值的结果）；
2. 启用 RTK 时进行 RTK 过滤，并对读取类工具启用自动检测保护；
3. 对搜索类工具进行 grep 折叠；
4. 其余情况按字节预算截断。

只有当上游决策是普通 accept 时，才把决策与上游合并。block 或结构化值优先。

### 4.3 提示词塑形

提示词塑形是一个名为 `token-saver:prompt-shaping` 的系统提示词 section，order 为 9500，`interpolate: false`。它的文本提供函数读取实时级别设置，因此修改后会在下一次组装时生效，无需重新注册 section。两个级别都关闭时，section 贡献空字符串。

这遵循 DSH 的文档规则：用 `ctx.systemPrompt.section()` 添加提示词文本，而不是监听 `system-prompt/assemble`。

### 4.4 本地响应

有些请求根本不需要模型：配额探测、前缀提取、会话标题、建议探测、文件路径提取。插件识别一小类形状，并用 usage 为零的合成流回答。识别需要正向证据，例如 `Command:`/`Output:` 配对或 `[SUGGESTION MODE:` 标记；单个关键词不足以匹配。

### 4.5 压力

pre-step 钩子读取 token meter，并把压力与两个阈值比较。超过第二个阈值时，它请求压缩引擎作为副作用进行压缩。它从不改写该步骤的消息。

### 4.6 状态

`$DSH_HOME/token-saver/` 下有两个小 JSON 文件：Web 面板写入的实时覆盖 `settings.json`，以及累计字节计数 `stats.json`。两者都失败放行。插件不维护数据库，也没有后台进程。

## 5. 核心概念

**工具结果压缩。** 用更小的文本替换工具结果文本，同时保留读者需要的内容。

**截断。** 在字节预算内保留头部和尾部，可选按行边界切割，并带有明确的省略标记。

**grep 折叠。** 保留匹配行及上下文，用标记表示省略的间隔和被截断的匹配。

**RTK 过滤器。** 针对 diff、状态、日志、树、表格和构建输出的形状感知压缩器。它们有损，并带有标记。

**提示词塑形。** Caveman 和 Ponytail 文本，要求模型简洁作答，同时保留精确的代码、路径、命令、错误和 URL。

**本地响应。** 不调用模型而生成的合成模型流。

**节省量。** 原文与压缩后字节数之差，只在压缩文本真正到达模型时累计。

## 6. 技术设计决策

### 6.1 选择 post-execute 而非提示词组装

在 `tools/post-execute` 压缩，保留了模型对工具结果的视图，也避免改写冻结的 LLM 请求。agent 循环的请求是会话日志的纯函数，并被深度冻结；修改它既不受支持，也不稳定。

### 6.2 单一导出形式

包导出 `name`、`Config`、`inject` 和 `apply`，不再同时导出默认对象。DSH 的插件加载器只接受一种形式，混用会让加载路径产生歧义。

### 6.3 Standard Schema 配置

`Config` 暴露 `~standard`，因此 DSH 在激活时校验行配置并拒绝非法值。`resolveConfig` 仍可供希望获得宽容默认值的程序化调用方使用，但 Host 路径是严格的。

### 6.4 按次计量

每次工具调用创建自己的累加器。累加器只合并进共享总量一次，并且只在压缩结果真正返回时合并。这避免了重复计数，也让 `calls` 和 `blocks` 保持诚实。

### 6.5 多块重建

当结果包含多个文本块时，压缩文本按各块原始 UTF-8 字节占比分配。这保持了块边界的意义，避免把多块结果塌缩成一块。

### 6.6 两层配置

Cordis 行配置是持久层。Web 面板把实时覆盖写入 `settings.json`。面板是便利工具，不是部署配置的第二个真相来源。

### 6.7 不在运行时替换提供方

DSH 通过 `cordis.yml` 选择压缩提供方。插件不在运行时修改服务注册表。因此 `replaceBasicCompaction` 只记录警告，不改变任何东西。LLM 摘要引擎仍然导出，供把它接入为提供方的 Host 使用。

## 7. 插件刻意不做的事

- 不总结对话。
- 不改变模型、温度或路由。
- 不通过组装瀑布改写系统提示词。
- 不修改 LLM 请求。
- 不替换压缩提供方。
- 不把提示词或工具输出写入磁盘。
- 不声称无法测量的 token 数。

## 8. 评估

基准测试在合成工具输出上测量 UTF-8 字节缩减，覆盖五种形状：大 diff、grep 结果、find 结果、构建日志和表格。结果在 58% 到 93% 之间。方法见 [benchmark-methodology](benchmark-methodology.md)，原始表格见 [benchmark-results](benchmark-results.md)。

这些数字是测试夹具的属性，不是对真实仓库的承诺。正确的解读是：对于这些形状，策略在保留信息部分的同时去掉了大部分字节。

## 9. 未来方向

- **提供方集成。** 把导出的 LLM 摘要引擎接入有文档的压缩提供方，而不是停留在导出。
- **感知 token 的预算。** 接受 tokenizer 回调，使预算在 Host 提供分词器时可以用 token 表达，同时保留字节作为回退。
- **自适应阈值。** 从观察到的结果大小学习每种工具的预算，而不是固定字节数。
- **更好的标记。** 标准化省略标记，让其他工具能检测并展开压缩内容。
- **本地响应覆盖。** 只在能够无歧义识别时增加探测。覆盖本身不是目标。
- **跨插件协作。** 发布一个小接口，让其他插件声明"不要压缩我的输出"或"这个结果已经压缩过"。

## 10. 结论

Token Saver 是一个范围很窄的小插件：上下文浪费在工具输出上，而在工具接缝处做一个谨慎、可选、失败放行的压缩器，可以在不改变模型能力的前提下回收其中大部分。设计遵循 DSH 受支持的扩展点，保持冻结请求不变，并只报告它真正测量到的内容。
